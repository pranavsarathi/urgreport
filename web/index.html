What is Pre-Simulation RTL Coverage Analysis?

          

            Commercial simulators (like Synopsys VCS + URG) generate coverage reports after executing dynamic waveform simulation.
            This tool performs static AST and stimulus reasoning on your RTL and Testbench before running simulation.
            It catches verification holes, omitted branches, unexercised counters, and unobserved DUT outputs early in the student design cycle.
          

        


        

          
Pre-Simulation Static Inference Terminology

          

            

              ✓ STIMULUS EVIDENCE FOUND / ✓ STATICALLY REACHABLE
              
Direct evidence exists in the testbench (assignments, clock edges, reset assertion) capable of satisfying the condition or reaching the state.

            

            

              ⚠ POTENTIALLY UNTESTED
              
The RTL structure or condition exists, but no testbench stimulus or sequence was found that drives the required values or polarities.

            

            

              ? INSUFFICIENT EVIDENCE / ⚠ ANALYSIS UNCERTAIN
              
The condition depends on multi-cycle loops, external task side-effects, or complex dynamic state that cannot be guaranteed without runtime simulation.

            

            

              ⚠ OUTPUT NOT VERIFIED
              
A DUT output is stimulated or modified, but the testbench never checks or observes it with assert(), if (out != exp), or $display.

            

          

        


        

          
Lightweight Dataflow & Boundary Analysis

          

            The engine traces dataflow chains: DUT Inputs → Internal Registers / Counters → Comparison Operators → Control Flags → FSM Next State.
            For arithmetic comparisons (e.g. counter >= THRESHOLD), it resolves parameters and identifies boundary targets (e.g., threshold count, rollover) needed for complete coverage.
